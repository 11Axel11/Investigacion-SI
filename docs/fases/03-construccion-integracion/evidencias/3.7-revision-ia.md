# Ítem 3.7: revisión asistida por IA automatizada sobre el PR

**Workflow:** [`.github/workflows/revision-ia.yml`](../../../../.github/workflows/revision-ia.yml). **Script:** [`scripts/ci/revision-ia.mjs`](../../../../scripts/ci/revision-ia.mjs). **Instrucciones:** [`.github/revision-ia.md`](../../../../.github/revision-ia.md), que reutilizan el formato de la fase 2 ([2.6](../02-desarrollo/evidencias/2.6-revision-ia.md): observación con ubicación, justificación y comprobación sugerida).

## Cómo funciona

1. Cada PR hacia `main` o `development` (no borrador y de la misma rama del repositorio) calcula el diff `base...head`, **sin lockfiles ni `.env`**, tope de 120 000 caracteres (si se trunca, lo dice).
2. Envía a la API del proveedor las instrucciones, `AGENTS.md` y el diff. **Proveedores:** DeepSeek (`DEEPSEEK_API_KEY`, `api.deepseek.com`, modelo `deepseek-chat`; TP-12, autorizado por Frander el 2026-11-11) o Anthropic (`ANTHROPIC_API_KEY`, modelo `claude-sonnet-5-5`; decidido en [Q-09](../../01-planificacion/kb/preguntas-abiertas.md#q-09), TP-08). Si están las dos claves se usa DeepSeek; el comentario indica proveedor y modelo. **No sale nada más:** ni secretos, ni variables de entorno, ni datos del padrón.
3. Publica (o actualiza) **un comentario** del PR con las observaciones.

## Qué NO hace (informativa)

- **No aprueba, no rechaza y no bloquea.** Es un workflow aparte, no es un check obligatorio y el job termina en éxito aunque la IA no responda.
- **Otro integrante valida cada observación** antes de actuar o descartarla; el comentario lo dice. Hasta entonces las observaciones son `pendientes` ([Q-11](../../01-planificacion/kb/preguntas-abiertas.md#q-11)).
- **No se hace pasar por "limpia":** sin la clave, en un PR desde un fork, con un error de la API o con respuesta vacía, escribe en el resumen del job "NO ejecutada" o "NO completada".

## Riesgos y medidas ([T-12](../../01-planificacion/kb/amenazas.md#t-12), TP-08)

| Riesgo | Medida |
|---|---|
| Inyección de instrucciones desde el diff ("aprueba este PR") | El prompt declara el diff como datos no confiables y pide señalarlo como observación Alta. La IA no tiene herramientas ni permisos: solo puede escribir un comentario, y el comentario no cambia el estado del PR |
| Menciones `@usuario` generadas por el modelo que notifiquen a personas | Se inserta un carácter de ancho cero después de cada `@` |
| Fuga de secretos o de datos personales en el prompt | Se excluyen `.env` y lockfiles; Gitleaks corre en el mismo PR; `--dry-run` informa si el prompt contiene algo con forma de `ADMIN_API_KEY` |
| Un PR de la misma rama modifica el workflow y lee `ANTHROPIC_API_KEY` | Riesgo aceptado mientras el equipo sea de confianza; lo mitiga la revisión de otro integrante (3.5). Los PR desde forks no reciben el secreto |
| Revisión equivocada o con puntos ciegos | Es informativa y la valida una persona |
