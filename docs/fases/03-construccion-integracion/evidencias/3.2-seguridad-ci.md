# Ítem 3.2: Semgrep CE, Gitleaks y OSV-Scanner en CI

**Script:** [`scripts/ci/seguridad-ci.sh`](../../../../scripts/ci/seguridad-ci.sh). **Job:** `seguridad`. Herramientas con versión y checksum SHA-256 fijados en [`scripts/ci/instalar-herramienta.sh`](../../../../scripts/ci/instalar-herramienta.sh): Semgrep 1.184.0, Gitleaks 8.30.1, OSV-Scanner 2.7.1.

## Qué bloquea y códigos de salida

| Herramienta | Código | Significado | ¿Bloquea? |
|---|---|---|---|
| Semgrep CE (5 reglas propias, `.semgrep/observatorio.yml`) | 0 | sin hallazgos | no |
| | 1 | hay hallazgos (`--error`) | **sí** |
| | otro | no pudo ejecutarse | **sí (incompleto)** |
| Gitleaks (historial y árbol, `.gitleaks.toml`) | 0 / 1 / otro | sin secretos / secretos / no pudo ejecutarse | no / **sí** / **sí (incompleto)** |
| `.env` versionado | — | cualquier `.env` rastreado por git (excepto `.example`) | **sí** |
| OSV-Scanner + compuerta (`scripts/ci/osv-gate.mjs`) | 0 | sin avisos con gravedad CVSS ≥ 7.0 sin excepción vigente | no |
| | 1 | hay avisos de gravedad **alta o crítica (≥ 7.0)** sin excepción vigente, o una excepción vencida | **sí** |
| | 2 | reporte ausente, ilegible o excepciones inválidas | **sí (incompleto)** |
| `seguridad-ci.sh` | 0 / 1 / 2 | limpio / hay hallazgos / **incompleto (tiene prioridad)** | 1 y 2 bloquean |

**Regla central:** un análisis que no pudo ejecutarse es **incompleto y bloquea**; nunca se interpreta como aprobado. La compuerta de OSV se probó con un reporte inexistente (código 2), un JSON inválido (2), una excepción vencida (1) y el estado real (0).

**Actualizar una herramienta (procedimiento manual):** Renovate no toca `scripts/ci/instalar-herramienta.sh` (la versión aparece dos veces en cada URL y el checksum no es una dependencia que Renovate entienda). Para subir de versión: cambiar la versión en la URL y copiar el SHA-256 del archivo de checksums de la release en el mismo PR. Si alguien cambia la versión sin el checksum, el job falla con «Checksum inválido»: falla cerrado, no instala nada sin verificar.

Los avisos de OSV con gravedad < 7.0 se **informan** en `reportes/osv-resumen.txt` y no bloquean; se atienden con las actualizaciones de Renovate ([`renovate.json`](../../../../renovate.json)).

## Cómo reproducirlo

```
brew install semgrep gitleaks osv-scanner    # o scripts/ci/instalar-herramienta.sh <herramienta> en Linux
scripts/ci/seguridad-ci.sh                    # reportes en ./reportes (no se versionan)
```

Reportes: `semgrep.json`, `gitleaks-historial.json`, `gitleaks-arbol.json` (valores redactados), `osv.json` y `osv-resumen.txt`. En CI se suben como artefacto `seguridad-<sha del commit>`.

**Límites.** OSV-Scanner solo analiza los lockfiles (no el sistema operativo de la imagen: eso lo cubre Trivy en [3.3](3.3-3.4-imagenes-y-politicas.md)). Los checksums de las herramientas vienen de la misma release que el binario: detectan descargas corruptas o alteradas en tránsito, no una release comprometida en origen.
