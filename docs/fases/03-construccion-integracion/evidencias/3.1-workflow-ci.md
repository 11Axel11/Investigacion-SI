# Ítem 3.1: workflow de CI por pull request

**Archivo:** [`.github/workflows/ci.yml`](../../../../.github/workflows/ci.yml). **Se ejecuta en:** `pull_request` y `push` hacia `main` y `development`.

| Job | Qué hace | Comandos |
|---|---|---|
| `backend` | Instala con el lockfile, lint, compila y corre las suites | `npm ci`, `npm run lint`, `npm run build`, `node --test` de `admin-key`, `tse` y `oij` |
| `frontend` | Instala con el lockfile, lint, tipos, pruebas y compila | `npm ci`, `npm run lint`, `tsc --noEmit`, `npm run test:operator`, `npm run build` |
| `seguridad` | Semgrep CE, Gitleaks y OSV-Scanner ([3.2](3.2-seguridad-ci.md)) | `scripts/ci/seguridad-ci.sh` |
| `politicas` | Conftest/OPA ([3.4](3.3-3.4-imagenes-y-politicas.md)) | `scripts/politicas.sh` |
| `imagenes` | Imágenes candidatas, Trivy y SBOM ([3.3](3.3-3.4-imagenes-y-politicas.md)) | `scripts/ci/imagenes-ci.sh` |
| `resultado` | **Único check obligatorio**: falla si cualquier job falló, se omitió o se canceló ([3.6](3.6-bloqueo-demostrado.md)) | — |
| `fusion` | Solo tras fusionar: registra el commit resultante ([3.8](3.8-commit-fusionado.md)) | — |

**Ambiente aislado y datos ficticios.** Cada job corre en un `ubuntu-latest` limpio. Las pruebas no necesitan base de datos: usan repositorios y servicios simulados y ZIP **inventados** armados en la propia prueba (`backend/scripts/tse.test.cjs`); ninguna lee el padrón real, `.env` ni la red de terceros. No hay secretos en el workflow.

**Instalación con lockfiles.** `npm ci` falla si `package.json` y `package-lock.json` no coinciden; el único lockfile es `package-lock.json` ([Q-05](../../01-planificacion/kb/preguntas-abiertas.md#q-05)). Node 22, igual que las imágenes.

**Comandos locales equivalentes.** `scripts/verificar.sh` (fase 2) ejecuta lo mismo salvo las imágenes; `scripts/ci/seguridad-ci.sh`, `scripts/politicas.sh` y `scripts/ci/imagenes-ci.sh` ejecutan cada job en la computadora. Verificación sintáctica del workflow: `actionlint .github/workflows/*.yml` (sin errores).

**Identificación del commit.** En un PR el commit evaluado es la punta de la rama (`github.event.pull_request.head.sha`), no el commit de fusión temporal de GitHub; los artefactos se nombran con ese SHA.
