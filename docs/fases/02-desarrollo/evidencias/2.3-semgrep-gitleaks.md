# Ítem 2.3: Semgrep CE y Gitleaks

**Fecha:** 2026-11-11. **Herramientas:** Semgrep CE 1.184.0 y Gitleaks 8.30.1 (instalados con Homebrew por Frander, tras negarse la descarga de imágenes Docker). Ejecución local, sin enviar código ni métricas a terceros (`--metrics=off`, sin registros externos).

## Alcance

| Herramienta | Qué analiza | Configuración | Qué cubre |
|---|---|---|---|
| Semgrep CE | `backend/src` y `frontend` (TypeScript) | [.semgrep/observatorio.yml](../../../../.semgrep/observatorio.yml), solo reglas propias | 5 reglas ligadas a la KB: `@Post` sin `AdminKeyGuard` (T-01), comparación no constante de la clave (T-01), SQL crudo con interpolación (T-13), `NEXT_PUBLIC_*` con nombre de secreto (T-01, Q-02) y clave en `localStorage`/`sessionStorage`/cookie (Q-02) |
| Gitleaks | Historial completo de git y árbol de trabajo | [.gitleaks.toml](../../../../.gitleaks.toml): reglas por defecto + `observatorio-admin-api-key` | Secretos versionados o presentes en archivos; valor de `ADMIN_API_KEY` de 32 o más caracteres |

**Qué queda fuera.** Semgrep no analiza dependencias (eso es auditoría de paquetes, fase 3), ni configuración de despliegue, ni lógica de negocio. Las reglas propias son patrones sintácticos: no detectan un guard aplicado de otra forma (p. ej. a nivel de módulo) y lo señalarían como falso positivo. Gitleaks no ve secretos sin forma reconocible. Se excluyen de Gitleaks `node_modules`, `.next`, `dist` y `package-lock.json` (generados e ignorados por git; los hallazgos que había eran identificadores de Next.js). Las claves ficticias de las pruebas están en la lista de permitidos.

## Demostración con defectos controlados

Se hizo en una copia temporal fuera del repositorio (nada de esto se versionó). Se agregaron un controlador con `@Post` sin guard, una comparación `x === process.env.ADMIN_API_KEY`, un `query` con plantilla interpolada, una variable `NEXT_PUBLIC_ADMIN_API_KEY`, un `localStorage.setItem(..., adminKey)` y un archivo con `ADMIN_API_KEY=` y un valor **ficticio** de 40 caracteres.

| Defecto | Detectado por | Ubicación en la copia |
|---|---|---|
| `@Post` sin guard | `observatorio-post-sin-admin-guard` | `backend/src/oij/defecto.controller.ts:4` |
| Comparación `===` con la clave | `observatorio-comparacion-clave-no-constante` | `defecto.controller.ts:6` |
| SQL con interpolación | `observatorio-sql-con-interpolacion` | `defecto.controller.ts:7` |
| `NEXT_PUBLIC_…_KEY` | `observatorio-secreto-en-variable-publica` | `frontend/lib/defecto.ts:1` |
| Clave en `localStorage` | `observatorio-clave-admin-en-almacenamiento-del-navegador` | `frontend/lib/almacena.ts:1` |
| Secreto ficticio | Gitleaks `observatorio-admin-api-key` | `backend/secreto-ficticio.txt:1` (valor redactado) |

`scripts/seguridad.sh` terminó con código 1 en la copia con defectos y con 0 en el repositorio real. El mismo código real (con `@UseGuards(AdminKeyGuard)` en los tres POST y comparación con `timingSafeEqual`) no genera hallazgos, lo que comprueba que las reglas no marcan el código correcto.

## Cómo ejecutarlo

```
brew install semgrep gitleaks     # una vez
scripts/seguridad.sh              # 0 sin hallazgos, 1 con hallazgos, 2 falta una herramienta
scripts/verificar.sh              # incluye seguridad; también lo llama el hook Stop
```

## Ajustes del 2026-11-11

- **Regla `observatorio-post-sin-admin-guard`:** ya no marca un `@UseGuards(AdminKeyGuard)` aplicado a nivel de controlador (R-06). Comprobado con 3 controladores de muestra: solo marca el que no tiene guard.
- **`.env` locales:** `gitleaks dir` no respeta `.gitignore` y marcaba `backend/.env` (clave real del operador, nunca versionada). Se excluyen del escaneo del árbol y `seguridad.sh` falla si algún `.env` está versionado (excepto `.example`); `gitleaks git` sigue escaneando todo el historial. El archivo no se leyó.
